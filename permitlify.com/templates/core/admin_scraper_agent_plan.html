What this page is. A reusable runbook documenting the exact HTTP-level inspection steps used to build each scraper engine. Every per-source scraper lives in its own file under core/scrapers/ — accela.py today, tyler_energov.py / opengov.py tomorrow — sharing one toolkit (core/scrapers/base.py: proxy-aware HTTP, ASP.NET state parser, GPT-OSS inference). When adding a new source: probe the network, isolate search/list/detail endpoints, capture the form-state contract, drop a new file alongside accela.py, hand the cleaned page to oss_extract(). Done.

Accela ASP.NET WebForms
Verified live against Wyandotte County KS (aca-prod.accela.com/UG) — same wire shape on every Accela tenant.
Beta · HTTP + OSS
Module: core/scrapers/accela.py
Shared: core/scrapers/base.py
Parser: openai-gpt-oss-20b
Proxy-aware · ~$0.0001/page
Discovery steps
1
Open the search page in DevTools → Network tab
Navigate to the agency’s CapHome.aspx (e.g. https://aca-prod.accela.com/UG/Cap/CapHome.aspx?module=Building&TabName=Building), open Chrome DevTools → Network, set a date range, click Search. Note the single POST that fires back to the same URL.
2
Capture the search POST body
ASP.NET WebForms posts the entire form back. The fields that actually drive the search are:
  • __EVENTTARGET = ctl00$PlaceHolderMain$btnNewSearch
  • __VIEWSTATE + __VIEWSTATEGENERATOR (carried from the GET)
  • txtGSStartDate / txtGSEndDate in MM/DD/YYYY
Tenant variance: some agencies also require __EVENTVALIDATION; Wyandotte UG does not. Forward whichever hidden inputs the GET response contains — the parse_webforms_state() helper does this generically.
# core/scraper_accela_http.py form = { '__EVENTTARGET': 'ctl00$PlaceHolderMain$btnNewSearch', '__VIEWSTATE': state['__VIEWSTATE'], '__VIEWSTATEGENERATOR': state['__VIEWSTATEGENERATOR'], 'ctl00$PlaceHolderMain$generalSearchForm$txtGSStartDate': '04/01/2026', 'ctl00$PlaceHolderMain$generalSearchForm$txtGSEndDate': '04/30/2026', }
3
Decode the pagination convention
Click page 2, page 3, page 4 — record each __EVENTTARGET. Wyandotte uses positional control IDs:
  • ctl00$…$gdvPermitList$ctl13$ctl03 → page 2
  • ctl00$…$gdvPermitList$ctl13$ctl04 → page 3
  • … up to ctl12 → page 11
ViewState rotates on every postback, so re-parse it from the previous response before issuing the next page request. paginate_next(prev_html, …, page_index=N) handles this.
4
Identify the detail-page URL shape
Click any row → record the URL: /UG/Cap/CapDetail.aspx?Module=Building&capID1=…&capID2=…&capID3=…&agencyCode=UG. Pull capID1/2/3 straight off the row links in the search-results HTML. Plain GET — no postback needed for the initial load.
5
Expand the “Show More” section
Critical caveat: contractor, owner and valuation are hidden behind a collapsed accordion whose postback target id contains the literal string MoreDetail. Without expanding it the parser sees only permit number + status + applied date and the contact_completeness sub-score collapses. fetch_detail(url, expand_more=True) issues the extra POST automatically.
6
Clean the HTML before sending to the LLM
Strip <script>, <style>, <meta>, <link>, <noscript> and HTML comments. A typical CapDetail page shrinks 65-70 % (300 KB → ~90 KB), which is what makes a single-cent batch budget viable. clean_html(raw) in the same module.
7
Parse with GPT-OSS-20B via DigitalOcean
POST https://inference.do-ai.run/v1/chat/completions with model openai-gpt-oss-20b, temperature 0, max_tokens 1500. Prompt = the admin-editable EXTRACT_SYSTEM_PROMPT (Permitlify multi-dimensional scoring schema with 9 sub-scores, 12 signal flags, tags + next-action) + the cleaned HTML. Strict JSON reply, parsed via the existing _extract_json() + _normalise_permit() helpers so the row that lands in the permits table has the same shape as Claude’s output.
Operational notes
·
  • Cookies. Thread ASP.NET_SessionId across every request — the helpers in scrapers/base.py persist them in a single dict per run.
  • User-Agent. Identify as PermitlifyBot/1.0 (+https://permitlify.com) — some tenants 403 on the default urllib UA.
  • Proxy. Set the Outbound HTTP proxy if the agency throttles App Platform IPs. Format: user:password@host:port. Every helper in scrapers/base goes through build_proxy_opener() automatically.
  • Rate. 1 search + 1 detail-with-expand per record ≈ 2 GETs/POSTs. Add 250 ms between detail fetches as a courtesy throttle.
  • Failover. If the OSS call returns malformed JSON twice, the worker logs the page id and skips it (rather than crashing the whole batch).
  • Cost. ~30 KB cleaned HTML × ~7,500 input tokens × $0.03/M = $0.000225 per page. 10,000 pages/month ≈ $2.25.

Tyler EnerGov
SPA architecture (Angular). Search is a JSON API, detail is a JSON API — no HTML scraping needed once the auth token is captured.
Planned
1
Inspect the JSON search endpoint
Open DevTools → Network → XHR. Search → look for a POST to a path like /api/permits/search returning JSON. Capture the request body shape (date range, status filter, page).
2
Capture the bearer token
EnerGov SPAs typically sign requests with Authorization: Bearer … minted by an anonymous-token endpoint on first page load. Replicate that handshake once per scrape session.
3
Skip the LLM for clean JSON
When the API already returns structured fields, run them through _normalise_permit() directly and only fall back to the OSS parser for fields that need classification (trade, scope summary, lead score).
🌆
OpenGov / ViewPoint Cloud
Public REST endpoints under /api/v1/permits. Pagination is cursor-based; detail is one GET per record.
Planned
1
Locate the public REST root
Many OpenGov tenants expose a documented Swagger schema at /api/docs. List → detail → applicant follows standard REST conventions; no postback shenanigans.
2
Walk the cursor
Paginate with ?cursor=…&limit=100 until the response’s next field is null. Detail GETs return JSON; same fast-path as EnerGov.

Template — adding a new municipal source
Copy this checklist into a fresh section above when bringing on a new platform.
Reusable
A
Probe
DevTools → Network. Capture every request the search + pagination + detail flows fire. Note method, URL, headers, body shape.
B
Isolate the smallest reproducible request
curl the search call from the terminal until it returns the same HTML/JSON the browser sees. Strip every header that isn’t required.
C
Codify state-handling
For WebForms: parse __VIEWSTATE + carry cookies. For SPAs: capture the auth token. For REST: just thread the API key.
D
Walk pagination
Verify pages 2, 3, last. Record the convention exactly so the helper can compute target N programmatically.
E
Detail fetch + expand
Always check whether the detail page hides high-value fields (contractor, valuation) behind an expand control. Issue the expand call before parsing.
F
Hand off to OSS parser
Clean the HTML, prepend EXTRACT_SYSTEM_PROMPT, call oss_complete(), normalise, upsert. Done.
