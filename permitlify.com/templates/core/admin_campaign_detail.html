⏱ Automatic sending (cron) A campaign only ships when something pokes the dispatcher on a schedule. Nothing sends just by clicking Start sending — that flips the status to sending; the cron does the actual mailing.

  1. Enable it (one-time). Add the workflow file .github/workflows/campaigns_cron.yml to the GitHub repo, then set the repo secret SCRAPER_INGEST_KEY (same value as the scraper-ingest / recovery-email crons). It then calls the tick endpoint every 15 minutes and any campaign in the sending state mails automatically. No server changes needed.
  2. Each tick runs the daily auto-pull top-up, then sends up to per_tick (20) recipients per active campaign, still bounded by the Daily cap below.
  3. Pacing: cap × ticks/day sets your ceiling. e.g. cap 200 + a tick every 15 min ≈ a gentle drip across the day — easy on Gmail/Outlook reputation while a domain warms up.
Cron endpoint (any external scheduler can call this)
curl -X POST -H "X-Scraper-Key: <SCRAPER_INGEST_KEY>" \
  "https://permitlify.com/api/cron/campaigns/tick/?per_tick=20"
Auth = the same SCRAPER_INGEST_KEY used by the scraper ingest & recovery-email crons. Header X-Scraper-Key or ?key= querystring both work. Idempotent & lock-safe, so overlapping calls never double-send.
GitHub Actions workflow YAML — copy to .github/workflows/campaigns_cron.yml 
{% verbatim %}name: Campaigns cron
on:
  schedule:
    - cron: '*/15 * * * *'   # every 15 min (best-effort)
  workflow_dispatch: {}
concurrency:
  group: campaigns-cron
  cancel-in-progress: false
jobs:
  tick:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - name: Fire campaigns tick
        env:
          SCRAPER_INGEST_KEY: ${{ secrets.SCRAPER_INGEST_KEY }}
        run: |
          curl -fsS -X POST -H "X-Scraper-Key: $SCRAPER_INGEST_KEY" \
            "https://permitlify.com/api/cron/campaigns/tick/?per_tick=20"{% endverbatim %}
Then add a repo secret named SCRAPER_INGEST_KEY under Settings → Secrets → Actions. Committing files under .github/workflows/ requires a token with the workflow scope.
Manual run (server shell) — e.g. to test or to send immediately
python manage.py campaigns_tick --campaign {{ c.id }} --per-tick 20
